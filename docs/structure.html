27MB짜리 엑셀 파일을
서버 없이 지도로 만드는 법

「내 예산으로 서울 어디?」는 서버가 없습니다. GitHub Pages는 파일만 내려줄 뿐 계산을 대신해 주지 않습니다. 그런데도 32만 건을 훑는 필터가 25밀리초 만에 반응합니다. 그 요령을 세 장의 그림으로 풀었습니다.

전체 그림 Pipeline

핵심은 일을 두 번에 나눠 하는 것입니다. 무거운 계산은 내 노트북에서 미리 끝내고, 브라우저에는 잘게 쪼갠 결과만 보냅니다.

빌드 타임 — 내 컴퓨터, 파이썬, 딱 한 번 런타임 — 사용자 브라우저, 자바스크립트, 매번

왜 굳이 쪼갰나 — 32만 행을 한 파일로 보내면 첫 화면이 뜨기까지 수십 초가 걸립니다. 반면 서울 지도를 칠하는 데 필요한 건 “구별 몇 건”이라는 숫자 25개뿐입니다. 그래서 집계만 먼저 보내고(957바이트), 상세 거래는 사용자가 그 구를 실제로 눌렀을 때 받습니다.

거래 한 건은 어떻게 저장되나 Row encoding

구 파일이 작은 두 번째 이유입니다. 거래 한 건을 객체가 아니라 배열로 저장하고, 반복되는 이름은 따로 빼서 번호로 가리킵니다.

rows[] 8칸의 의미 — 순서가 곧 스키마입니다
칸이름타입설명
0dongIdxintdongs 배열의 몇 번째인지
1complexIdxintcomplexes 배열의 몇 번째인지
2areaM2float전용면적 ㎡ (소수 1자리)
3floorint층. 지하는 음수, 알 수 없으면 0
4dealTypeint0 매매 · 1 전세 · 2 월세
5amountint만원. 매매는 거래가, 전세·월세는 보증금
6monthlyRentint만원. 월세만 값이 있고 나머지는 0
7datestringYYMMDD 6자리

월세만 특별 취급합니다 — 월세는 금액이 보증금과 월세 두 개라 “3억 이하”로 한 줄에 세울 수가 없습니다. 그래서 비교할 때만 보증금 + 월세 × 100 으로 환산해 한 축에 올리고, 화면에는 1억 + 45만 처럼 원래 값을 그대로 보여줍니다.

슬라이더를 움직이면 벌어지는 일 Runtime loop

서버에 묻지 않습니다. 이미 받아 둔 배열을 브라우저가 한 번 훑고 화면 세 곳을 다시 그립니다.

파일 구조 Files

빌드 도구도, 프레임워크도, npm install 도 없습니다. 저장소에 올린 파일이 그대로 웹사이트가 됩니다. 

저장소 루트 = 웹사이트 루트 (GitHub Pages)

index.html               대시보드 본체 (한 페이지)
assets/
  ├ app.js               필터 · 상태 · 렌더링 전부  30KB → 7.9KB
  └ style.css            Montage 토큰 기반 스타일   9.6KB → 2.2KB
data/                    ← 빌드 결과물. 손으로 고치지 않음
  ├ summary.json         25구 집계              → 957B
  ├ seoul-map.json       25구 SVG 경로           → 6.4KB
  └ gu/11010.json …      구별 거래 25개 파일      → 각 50~214KB

build_data.py            CSV → summary.json + gu/*.json
build_map.py             GeoJSON → seoul-map.json
seoul-apt-latest.csv     원본 27MB. 배포는 되지만 페이지가 부르지 않음
PRD.md                   기획서 · 데이터 계약

data/ 안의 파일은 사람이 편집하는 곳이 아닙니다. 원본 CSV가 바뀌면 build_data.py 를 다시 돌려서 통째로 새로 만듭니다.
